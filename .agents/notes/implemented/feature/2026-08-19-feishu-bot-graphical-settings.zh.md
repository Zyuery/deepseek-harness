# Agent Note: 飞书机器人图形化设置

Status: implemented

[English](2026-08-19-feishu-bot-graphical-settings.md) | 中文

## 问题

之前挂载飞书机器人就意味着启用，而且必须从启动环境获取凭据。Web 用户无法发现其配置，也无法在有意断开时保持插件已安装；而把 App Secret 放入普通设置，会将持久密钥放到为“可脱敏但可读”值设计的配置平面。

## 决定

`@zyuer/dsh-feishu-bot` 注册可实时生效的 `feishu-bot` 设置命名空间，其字段为 `enabled: false`、可选 `appId`、凭据引用 `FEISHU_APP_SECRET` 和 `requireMention: true`。浏览器导出以同一命名空间 key 向 `settings.plugin.item` 注册卡片，因此 Web profile 可从已安装插件发现卡片，无需重新构建前端。

卡片只通过 `credentials.set` 写入 App Secret，然后在一次带修订号栅栏的设置变更中写入 App ID、提及策略和启用标志。在 App ID 与已存在或新输入的 App Secret 都具备之前，启用控件不可用。Host 在连接前立即解析凭据，绝不将其值返回浏览器、配置输出、日志或会话事件。

Host 拥有一条串行的 Channel 替换生命周期。关闭的设置会注册卡片，但不分配 Lark 资源。有效的启用、实时设置更新或被引用凭据的更新都会替换 Channel；拆卸会先移除消息监听，再断开连接，并等待正在执行的替换链完成。

## 考虑过的替代方案

**仅使用启动环境配置。** 这会保持首个原型较小，但不提供可发现的 Web 配置，也无法区分“插件存在”与“运行时启用”。

**将 App Secret 存为 secret role 设置字段。** 脱敏可以阻止它进入普通设置响应，但凭据服务已经拥有来源优先级、Web 只写操作和环境遮蔽语义。重复该职责会为同一个值引入两个密钥存储。

**挂载插件时立即连接。** 这会保留以前的生命周期，但阻止用户在启用前安装和配置卡片；凭据缺失时，整个插件会变得不可用，而不是展示可用于修正的 UI。

## 验证

包测试覆盖关闭状态注册、配置门控、凭据优先保存、连接替换与拆卸、稳定的飞书到会话映射，以及模型可见的 `UserMessage` 投递。类型检查和包构建还会编译 Host 入口，以及作为 `./client` 导出的延迟 CJS 浏览器 factory。

## 结果

该包现在要求与声明的对等版本匹配的 DSH 设置、凭据、agent、持久化和 Web 客户端接口。图形化卡片只会出现在包含 Web app 组合包的 profile 中；仅包含 base 的自定义 profile 可以运行 Host 插件，但没有用于渲染配置的页面。作为交换，安装、配置、启用、密钥存储和拆卸成为相互分离的显式操作。
