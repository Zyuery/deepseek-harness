# Agent Note: 飞书机器人按 Turn 归属的流式回复

Status: implemented

[English](2026-08-20-feishu-bot-turn-streaming-replies.md) | 中文

## 问题

`agent.followup()` 只会把输入加入队列，不返回单条消息的完成状态或结果。在 `whenIdle()` 后读取最后一条助手消息，可能选中其他排队输入的输出；而在飞书消息处理器中等待完整模型运行，会延迟 Channel 去重和同一聊天的后续分发。连接被替换时，还必须在断开前停止所有输出观察，同时不能取消 DSH 已受理的工作。

## 决定

Controller 连接两个自有端口：DSH Agent 网关按顺序产生用户可见文本，Lark 回复网关则把这些文本写入一张回复入站消息的 Markdown 流式卡片。Lark 适配器使用官方 Channel 的 `stream()` API，并通过 `replyInThread` 保持群话题上下文。

DSH 网关创建带新稳定 ID 的 `UserMessage`，在调用 `agent.followup()` 前安装监听器，再通过 `agent/inbox/claimed` 将提示消息关联到唯一 Turn。网关只转发该 Turn 的 `assistant/chunk` 文本增量；某个步骤没有产生文本增量时，才用 `assistant/message` 补充用户可见文本；`turn/end` 结束生产器，并为未完成结果或没有用户可见文本的已完成 Turn 添加提示。提示消息被丢弃、Agent 被释放、写入器失败或连接停止观察时，都会明确终止生产器。

网关根据飞书应用、会话范围和当前 DSH 工作目录的稳定摘要生成每个 Session ID。新 Session 会把该工作目录记录为 `cwd`；网关在新建或恢复 Agent 时提供部署默认的提供方和模型，并在该 Agent 的上下文中安装插件配置的推理强度。插件默认使用 `off`，让具备推理能力的模型生成可供飞书卡片展示的回答正文，同时不暴露推理事件。因此，来自另一个工作目录的消息不会恢复模型上下文指向不同工作目录的 Session。

Channel 消息处理器启动 Controller 任务后立即返回，不等待模型执行。每个活动 Channel 拥有一个中止控制器，以及由它启动的准确回复任务集合。拆卸时先移除入站订阅，再中止输出观察，等待所有任务停稳，最后断开连接。停止观察不会取消 DSH Turn，已经提交的 Session 事件也不会回滚或作为替代回复重新发送。

## 考虑过的替代方案

**等待 `agent.whenIdle()` 后读取最新答案。** 整个 Agent 的 idle 可能覆盖多条排队 follow-up、steering 或注入工作，无法把选中的输出归属到一条飞书消息。

**把映射 Session 的每个事件都当成当前回复。** 新飞书消息到达时，Session 可能正在运行。仅靠 Session 身份无法区分当前 Turn 和排队提示消息之后所属的 Turn。

**在 SDK 消息处理器中等待回复。** 这会让 SDK 在整个模型运行期间保持逐聊天串行，但也会让事件一直处于处理中，并延迟去重。DSH 已经把普通 follow-up 串行化为独立 Turn，因此长时间等待应由插件自己的后台任务集合持有。

**只发送最终组装消息。** 实现更简单，但会放弃 MVP 的流式卡片行为，长时间工具调用期间也没有可见进度。

**只用飞书会话作为持久 Session 身份。** 这会让一个 Session 被多个 DSH 工作目录复用。恢复接口会保留已存储的 Session 元数据，而不是替换 `cwd`，因此只包含飞书会话的身份无法在提示词组装前安全修复或拒绝工作目录不匹配。

**不提供覆盖项，直接继承部署的推理强度。** 具备推理能力的模型可能在完成 Turn 时只产生推理块而没有用户可见文本，导致外部回复为空。插件的显式字段默认使用 `off`；操作人员接受相应取舍时，仍可填写模型提供方定义的其他值。

## 验证

包测试覆盖按工作目录隔离的 Session ID、默认模型与 `cwd` 创建元数据、Agent 级推理选择、目标 Turn 关联、无关事件过滤、有序文本增量、组装消息回退、仅含推理内容的完成提示、观察中止、卡片回复及话题参数、消息处理器立即返回和停稳拆卸。包类型检查与构建同时编译 Host 和浏览器导出。

## 结果

每条受理的文本消息都可能在排队的 DSH Turn 开始前创建占位卡片，因此并发飞书消息可能同时显示多张等待卡片。改变 DSH 进程的工作目录后，后续消息会映射到另一个 Session；原来的持久对话仍以原工作目录身份保存。关闭或替换 Channel 后，已受理的 DSH Turn 可以继续完成，但不会再更新飞书；持久结果仍保留在 DSH 中，而且不会重放，从而避免外部消息重复。默认使用 `off` 会放弃模型推理，以换取可直接展示的回答；操作人员可以配置模型提供方定义的其他推理强度。首版只复制用户可见文本，推理、工具、图片、文件、表情和交互式审批控件分别作为后续能力实现。
